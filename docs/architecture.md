# Structure

```
server/
  core/        HTTP router, auth, DB (node:sqlite), event bus, templates, time zones, public pages
  services/    Business logic that several modules share: contacts, sending (email/SMS), opportunities,
               workflow engine, reviews, GHL import
  modules/     One module per area: its own tables (migrations) + routes (register)
  modules/index.ts   Registry – register new modules here
  assets/forms/ Browser scripts and styles of the public forms (parts that `npm run build` minifies; docs/forms.md)
web/src/       React UI (one file per area under pages/)
tests/         Unit and end-to-end API tests (vitest)
```

## Adding a module

```ts
// server/modules/memberships.ts
import type { Module } from '../core/app.js';

export const membershipsModule: Module = {
  name: 'memberships',
  migrations: [['001-init', `CREATE TABLE courses (id TEXT PRIMARY KEY, location_id TEXT NOT NULL REFERENCES locations(id) ON DELETE CASCADE, …)`]],
  register(app) {
    app.router.get('/api/courses', 'location', (ctx) => app.db.all('SELECT * FROM courses WHERE location_id = ?', ctx.locationId));
    app.events.on('invoice.paid', (e) => { /* unlock access */ });
  },
};
```

…and register it in `server/modules/index.ts`. Never change migration names, only append new ones.

## Rules

- **Auth per route:** `public`, `user` (signed in), `admin`, `location` (signed in *or* API key + sub-account). Everything with `location` filters on `ctx.locationId`.
- **CSRF:** Writing requests with a cookie need the header `x-pghl: 1` (the UI does this automatically).
- **Events** (`app.events.emit(locationId, type, data)`) run after the response; workflows and webhooks hook into them. `data.contactId` starts workflows for that contact.
- **Permissions:** `app.guards` run after sign-in; the agency module checks the areas of restricted logins there (`server/core/permissions.ts` maps routes to areas). New modules register their routes there – the SaaS guard (`saas-gate.ts`) uses the same mapping to block areas outside the plan and to check limits on creation.
- **UI language:** Texts stay German in the code and go through `t()` from `web/src/i18n` (`const t = useT('bereich')`, the German text is the message ID); the English translations live per area in `web/src/i18n/en/*.ts`. `npm run i18n:check` keeps areas with `complete: true` in `web/src/i18n/registry.ts` complete. Each person's language is stored by `modules/language.ts` (`users.lang`, `/api/me/language`) – guide: [translating.md](translating.md) (English).
- **Performance:** no query per sub-account/row within a request (group instead, see `services/location-stats.ts`), an index in the module's own migration for every new `WHERE`/`ORDER BY` on large tables, read-only lists/reports through `cached()` (`core/cache.ts`) or `app.db.memo`, background jobs in slices of at most ~50 ms (`sliceTimer`), new pages with `lazyPages` – the rules with examples: [docs/performance.md](performance.md#rules-for-modules). `app.perf` (event loop, slow requests/queries, job times) → `GET /api/admin/metrics`.
- **Background jobs** via `app.onTick(fn)` (workflow waits, reminders, scheduled campaigns, subscription invoices, iCal sync, date triggers, backups).

## Reports: custom data sources

Reports & dashboards (`modules/reports.ts`, engine in `services/report-engine.ts`, built-in sources in `services/report-sources.ts`) read everything through the list `app.services.reportSources`. A module registers its table with a few lines – no matter whether it is registered before or after the reports module:

```ts
import type { ReportSource } from '../services/report-engine.js';
import { contactJoin, lookupTable } from '../services/report-sources.js';

const ticketContact = contactJoin('t.contact_id'); // optional: contact fields as “Contact: …”
const TICKETS: ReportSource = {
  key: 'tickets', label: 'Tickets', area: 'conversations',          // permission that client logins need (+ SaaS plan)
  from: 'tickets t', location: 't.location_id', dateField: 'created_at',
  requires: ['tickets'], countLabel: 'Anzahl Tickets', joins: ticketContact.joins,
  fields: [
    { key: 'created_at', label: 'Erstellt am', type: 'date', sql: 't.created_at' },
    { key: 'status', label: 'Status', type: 'enum', sql: 't.status', options: { open: 'Offen', closed: 'Geschlossen' } },
    { key: 'agent', label: 'Bearbeiter', type: 'string', sql: 't.assigned_to', lookup: lookupTable('users', 'name'), empty: 'Nicht zugewiesen' },
    { key: 'hours', label: 'Lösungszeit', type: 'number', sql: '(julianday(t.closed_at) - julianday(t.created_at)) * 24', format: 'number' },
    ...ticketContact.fields,
  ],
  calcs: [{ key: 'close_rate', label: 'Lösungsquote', sql: `100.0 * SUM(t.status = 'closed') / NULLIF(COUNT(*), 0)`, format: 'percent' }],
};
app.services.reportSources = [...(app.services.reportSources ?? []), TICKETS];
```

- `sql`, `from`, `joins` and `calcs` are fixed code – user values enter the query only as parameters; the engine itself appends the sub-account filter (`location IN (…)`), the period, filters, `LIMIT` and a time limit.
- Field types: `string`, `enum` (with `options`), `number` (`format`: number, money – in euros –, percent, days, minutes), `date` (ISO timestamp; grouping by day … hour in the sub-account's time zone), `boolean` (SQL returns 1/0), `tags` (JSON array). `lookup` translates IDs into names (and order, e.g. pipeline stages); `noGroup` for free text.
- Every source automatically gets the group *Sub-account*; sources with missing tables (`requires`) are hidden. A test that compiles all fields is in `tests/reports.test.ts`.
