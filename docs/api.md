# API

Base: `https://<your-domain>`. Create keys under **Settings → API & webhooks**; each key belongs to one sub-account.

Machine-readable: **OpenAPI 3.1** at `GET /api/openapi.json`, as a web page at `GET /api/docs.html` (both without a key). REST hooks, Zapier/Make/n8n, “Webhook received” and the HubSpot import: [docs/integrations.md](integrations.md).

```bash
KEY=pghl_…
# Create or update a contact (duplicates are merged by email/phone)
curl -X POST https://crm.example.com/api/contacts -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"first_name":"Anna","email":"anna@example.com","tags":["lead"],"custom":{"budget":"5000"}}'

# Search contacts
curl "https://crm.example.com/api/contacts?q=anna&tag=lead&limit=50" -H "Authorization: Bearer $KEY"

# Create an opportunity
curl -X POST https://crm.example.com/api/opportunities -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"pipeline_id":"…","contact_id":"…","value":1500}'
```

## Mobile app

Interface of the native [Android app](app.md#android-app). JSON, money in cents (`*_cents`) plus `currency` (`EUR`), times in ISO 8601 UTC, errors `{error}` in German. Every list row carries `location_id` and `location_name`; `?location=all` (default) combines all visible sub-accounts, `?location=<id>` takes one (someone else's → 403, unknown → 404). Areas that a customer login or its SaaS plan does not have are missing for `all` or return 403 with the reason.

**Sign-in:** `POST /api/mobile/pair` only with a session cookie + `x-pghl: 1` (login of the app's web view), body `{device_name, platform, app_version}` → `{token: "ghm_…", device_id, user: {id, name, email, role, permissions}}` (the token appears only in this response). All other calls use `Authorization: Bearer ghm_…` (optional `x-app-version`); unknown/signed out → 401, more than 300 requests/minute per device → 429. The token is valid only under `/api/mobile/*`.

## Webhooks

Outbound: `POST` to your URL with `{type, locationId, at, data}` and the headers `x-pghl-signature-256: sha256=<HMAC-SHA256(secret, body) hex>` (recommended) and `x-pghl-signature: sha256(secret + body)` (older method, stays for existing receivers). New: `call.missed`, `call.voicemail`, `call.completed` (`{contactId, callId, direction, status, from, to, duration, transcription}`), `voice_ai.completed` – AI call ended (`{contactId, callId, sessionId, outcome: booked|transferred|message|opportunity|task|sms_link|answered|hangup|voicemail|limit|error, outcomes, summary, next_step, appointmentId, taskId, opportunityId, message, transferred, turns, duration, from}`) and `google_review.received` (`{contactId?, rating, author, text, link, low}`). If an appointment is deleted in the connected Google/Outlook calendar, `appointment.status_changed` arrives with `status: "cancelled"` and `source: "google"|"microsoft"`. Without a workflow trigger of their own, but delivered to webhooks with `events: ["*"]` and REST hooks “Every event”: `contact.deleted` (`{contactId, erased?}` – also when several contacts are deleted, `erased: true` for GDPR erasure), `contact.merged` (`{contactId, contact, fromId}`), from project planning `task.updated` (`{contactId?, task, projectId, changed}`), `task.deleted` (`{contactId?, taskId, title, projectId, by}`), `task.commented` (`{contactId?, task, comment: {id, body}, mentions}`), `pm.project.deleted` (`{projectId, name}`), `timer.started`, `timer.stopped`, `time.logged` (each `{entry}`), `timesheet.submitted` (`{userId, week}`), `timesheet.decided` (`{userId, week, status}`), plus `sequence.enrolled` (`{contactId, sequenceId, enrollmentId, userId}`), `billing.cancel_requested` (`{contactId, subscription, productId, immediate}`) and `billing.plan_switched` (`{contactId, subscription, fromProductId, productId, product}`) from the customer's subscription page (`/abo/…`, [docs/dunning.md](dunning.md)).

Inbound (workflow trigger “Inbound webhook”): call the URL shown in the workflow with JSON `{email, phone, first_name, …, tags}` (`400` without email, phone or name). Trigger “Webhook received”: `POST /hooks/in/<token>` with any JSON (field mapping in the workflow, optional `X-Signature-256: sha256=<hmac>`, limit per URL, 429 above it) – [details](integrations.md#inbound-webhooks). Repeated deliveries are processed only once: for both workflow webhooks via the sender's delivery ID (`webhook-id`, `svix-id`, `Idempotency-Key`, `X-Idempotency-Key`, `X-Webhook-Id`, `X-Delivery-Id`, `X-GitHub-Delivery`, `X-Shopify-Webhook-Id` – response `{ok: true, duplicate: true}`), for SMS/email inbound (`/hooks/:locationId/sms|email?key=`) and for the support mailbox via the message ID (`MessageSid`, `payload.messageId`, `Message-Id`, also in `headers`). Stripe, Meta, Twilio calls, Telegram, Slack and the SMS/email providers already recognize repeats by their event IDs.

REST hooks (Zapier/Make/n8n): deliveries as `{id, event, type, location_id, occurred_at, contact_id, contact, data}` with `x-pghl-signature-256 = sha256=<HMAC-SHA256(secret, body)>`, `x-pghl-signature = sha256(secret + body)`, `x-pghl-event`, `x-pghl-delivery`, `x-pghl-attempt`; retry after 1 min / 5 min / 30 min / 2 h / 6 h, subscription switched off after three `410` responses. New event `task.completed` (`{contactId?, task}`) when a task is completed.

## Privacy (GDPR)

- `GET /api/contacts/:id/privacy-export` – all stored data about one contact in this sub-account as a JSON file (contact, notes, tasks, messages, appointments, forms, tickets, courses, community, attribution, partner data with the same email …; without tokens and secrets; other people's “only for me” documents only for admins and API keys).
| --- | --- |
| `GET /.well-known/oauth-protected-resource` (also `…/oauth-protected-resource/mcp`) | RFC 9728: `{resource: "https://<domain>/mcp", authorization_servers: ["https://<domain>"], scopes_supported: ["mcp", "mcp:read"]}` |
| `GET /.well-known/oauth-authorization-server` | RFC 8414 metadata: endpoints below, `code_challenge_methods_supported: ["S256"]`, grant types `authorization_code`, `refresh_token` |
| `POST /oauth/register` | RFC 7591 dynamic client registration `{client_name, redirect_uris, token_endpoint_auth_method?: none \| client_secret_post \| client_secret_basic, grant_types?, response_types?}` → `201 {client_id, client_secret?}`. Redirect URIs: https, http only for localhost/127.0.0.1, or a private scheme; no fragments |
| `GET /oauth/authorize` | `response_type=code`, `client_id`, `redirect_uri` (exact match), `code_challenge` + `code_challenge_method=S256` (required), `state`, `scope` (`mcp` or `mcp:read`), `resource` (optional, must be this server's `/mcp`). ## Limits

Requests without valid credentials are rejected at the headers. Body size: 1 MB on public routes (form uploads, inbound emails, community images and `/mcp` with a valid key: 12 MB), 12 MB with a login or key. `429` above 900 API requests or 120 public writes per minute and address. `limit` parameters are clamped to 1…maximum.
