## Why HyperLevel?

**Stop renting your CRM.** GoHighLevel costs **$97–$497 per month**, HubSpot's Professional tiers start
around **€800+ per month** and grow with every seat and contact. HyperLevel gives an agency or small business the
same toolbox for the price of a small server (≈ €5–15/month) – with unlimited users, contacts and
sub-accounts.

- **Own your data.** Everything lives in one SQLite file on *your* server: no vendor lock-in, no per-contact
  pricing, GDPR-friendly by design, back it up with `cp`. Import from GoHighLevel and HubSpot in a few clicks.
- **AI-native.** A built-in MCP server lets Claude, ChatGPT, Codex and other AI clients work your CRM through
  340+ tools – with the same permissions and audit log as a human. Plus an AI assistant for replies, a chatbot
  and an AI phone agent (bring your own Anthropic key).
- **Agency-ready.** Unlimited sub-accounts, client logins with per-area permissions, white-label branding and
  login domains, snapshots, and a SaaS mode to resell sub-accounts through your own Stripe.
- **Fair, flat pricing.** Self-hosted is 0 € with every feature. A hosted cloud is planned – Solo 49,99 €, Team & Company
  99,99 € or Agentur 199 € (white-label and unlimited client sub-accounts included) per month, net plus VAT, never per
  seat, no contact tiers – but it is **not open yet**: [gohyperlevel.com](https://gohyperlevel.com) takes sign-ups for the
  waitlist only. The cloud mode software is in the box for anyone who wants to run it ([docs/cloud.md](docs/cloud.md)).
- **Small and hackable.** No Postgres, Redis or queue – one process. Every feature is a module with its own
  tables and routes; adding yours doesn't mean forking the core ([CONTRIBUTING.md](CONTRIBUTING.md)).

## Quick start

On any Linux server with Docker and a domain pointing at it – **one command**, with automatic HTTPS:

```bash
curl -fsSL https://raw.githubusercontent.com/gohyperlevel/gohyperlevel/main/scripts/install.sh | bash
```

Or by hand, in **three commands**:

```bash
git clone https://github.com/gohyperlevel/gohyperlevel.git && cd gohyperlevel
cp .env.example .env                    # set PGHL_BASE_URL and PGHL_DOMAIN
docker compose --profile caddy up -d    # HyperLevel + Caddy (Let's Encrypt)
```

Optional profiles: `--profile openshorts` (Video-Studio engine) and `--profile nango` (self-hosted
[Nango](deploy/nango/README.md) for the Nango connector – Elastic License, see the licence notes there).

Open your domain and create the admin account on the setup page. Just looking around? Run it locally with
fictional demo data:

```bash
npm ci && npm run build
npm run demo:seed -- --data-dir ./demo-data
PGHL_DATA_DIR=./demo-data npm start     # http://localhost:4700 · demo@example.com / demo1234
```

More ways to deploy – Coolify, Railway, Render, Hostinger, plain Node: **[docs/deploy](docs/deploy/README.md)**.
A public try-it-out instance: **[demo mode](docs/demo-mode.md)** (`PGHL_DEMO_MODE=1` – seeded data, nightly
reset, nothing ever leaves the server).

templates, social posts and AI shorts, calendars and calls, Google reviews, blog posts, courses, community
posts, attribution, affiliates, reports and dashboards, tickets and help articles, project planning and time
tracking, wiki, team chat, invoices and quotes, sequences, webinars, Canvas boards, Living Boards, undo, SaaS
plans and the audit log. Every tool calls the regular REST API internally – permissions, validation and the
audit log apply unchanged. The live list comes from `tools/list`; the tools of each feature are named on its
page, the core ones in [docs/api.md](docs/api.md#mcp-server).

**Moving from Claude?** Connect the connector with agency scope and ask Claude to call `ghl_import_claude_project` in a
claude.ai project (instructions, knowledge files and chat links become a sub-account) or `ghl_upload_files` in a Claude Code
repository; `ghl_api` reaches every other route with the connection's own rights – see
[docs/ai-tools.md](docs/ai-tools.md#claude-projekte-umziehen).

The built-in **AI assistant** (per sub-account, your own Anthropic key, monthly limit) suggests replies,
summarises threads, answers website chats with hand-off to your team, drafts e-mails and powers the **AI
phone agent** that books appointments over Twilio. Details: [docs/ai-assistant.md](docs/ai-assistant.md).

## Android app

A native Android app (Kotlin, Jetpack Compose + Glance) wraps the web app and adds **13 home-screen
widgets** (cockpit, inbox with direct reply, tasks, appointments, pipeline, revenue, calls, reviews, voice
note …), quick actions and notifications without Firebase. It updates itself from your server
(`/android`, signed APK with checksum). Build it with your server address and package name:

```bash
cd android && ./gradlew assembleRelease -PgohighBaseUrl=https://crm.example.com -PgohighApplicationId=com.example.crm
```

See [android/README.md](android/README.md) and [docs/android-app.md](docs/android-app.md). The web app is
also an installable PWA with push notifications on every platform – on iPhone and iPad as a Home-Screen app with push and
badges, see [docs/ios-web-app.md](docs/ios-web-app.md).

## Architecture

```mermaid
flowchart LR
  subgraph Clients
    B[Browser · React SPA / PWA]
    A[Android app]
    M[AI clients via MCP]
    Z[Zapier · Make · n8n]
  end
  subgraph HyperLevel["HyperLevel – one Node.js 22 process"]
    R[HTTP router · auth · guards]
    MOD[Modules registry<br/>CRM · inbox · workflows · funnels · helpdesk · reports · …]
    T[Scheduler tick<br/>waits · reminders · syncs · backups]
  end
  DB[(SQLite<br/>node:sqlite)]
  B & A & M & Z --> R --> MOD --> DB
  T --> MOD
  MOD -. your credentials .-> X[SMTP/IMAP · Twilio · Meta · Stripe · Google/Microsoft · Anthropic · Postiz · OpenShorts]
```

- **Server:** TypeScript on Node.js 22 with the built-in `node:sqlite` – no ORM, no external database.
  Each feature is a module (`server/modules/*.ts`) with its own migrations and routes, registered in
  `server/modules/index.ts`; modules cooperate through hooks on `app.services` (workflow actions, MCP tools,
  report sources, catalogue entries …), so a missing module never breaks the core.
- **Web:** React 19 + Vite single-page app under `/app`, public pages (funnels, booking, portal, help center)
  rendered on the server.
- **Tests:** 4,500+ vitest unit and end-to-end API tests run against a real in-memory app.
- **Deploy:** one Docker image (multi-arch, ~70 MB), data on one volume.

Read more in [docs/architecture.md](docs/architecture.md) (German) and [CONTRIBUTING.md](CONTRIBUTING.md).

(dev setup, tests, the module/registry rules and how to add a connector) and the
[Code of Conduct](CODE_OF_CONDUCT.md). Pull requests need a one-time signature of the [CLA](CLA.md) (the CLA Assistant

Found a vulnerability? Please report it privately: [SECURITY.md](SECURITY.md). Recommending, hosting or setting up
HyperLevel for others: [partner program](docs/partner-program.md).

They are always labelled "Partner-Link" and only clicks per provider are counted – details in [docs/referrals.md](docs/referrals.md).
