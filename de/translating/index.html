Translating HyperLevel

Dieser Inhalt ist noch nicht in deiner Sprache verfügbar.

HyperLevel’s interface is written in German and ships an English translation of the areas people use most (phase 1 of the English UI) and of automations, marketing, the builders, projects, reports, the helpdesk, the social planner, the wiki and team chat, and courses (phase 2). This page explains how the language layer works, how to translate a page and how to add a language. The roadmap lists what comes next.

Choosing the language

Section titled “Choosing the language”
  • Signed in: the language saved at the user – Einstellungen → Mein Konto → Sprache or the language button in the sidebar’s account corner (next to Darstellung). It applies on every device.
  • Signed out (login, setup, the AI app consent screen): the language picked on this device before, else what the browser asks for (Accept-Language). The login card has a Deutsch · English switch; a choice made there is saved to the profile with the next sign-in.
  • When the browser asks for no supported language, the app is German.

The server side lives in server/modules/language.ts:

Route Auth
GET /api/language public { lang, locales } – the language Accept-Language asks for (weights honoured), German when none matches
GET /api/me/language user { lang, auto, locales } – the saved choice (or null) and the Accept-Language pick
PUT /api/me/language user { lang: "de" | "en" | null } – null follows the browser again

GET /api/me carries user.lang, so the app starts in the right language without another request. The column users.lang is added by the module’s own migration.

How it works

Section titled “How it works”

German is the source language: the German text in the code is the message id. A catalog maps it to another language.

  • useT(ns) in components: re-renders when the language changes and waits (inside the page’s Suspense boundary) until the namespace’s catalog is loaded. tr(ns) outside components – helpers, event handlers, toasts – translates with the language active at call time.
  • Lookup order: the namespace’s catalog, then core, then the German text. A typo can therefore never show a raw key.
  • {name} placeholders are filled from the second argument; placeholders without a value and merge tags such as {{contact.first_name}} stay as they are.
  • Plural forms follow Intl.PluralRules of the language; forms.other is the message id, a catalog may give one string or its own forms (zero, one, two, few, many, other).
  • Numbers, money and dates: fmtNumber, fmtMoney, fmtDate, fmtDateTime, fmtTime (and money, amount, d, dt, ago in api.ts) use the active language – German stays de-DE, English takes the regional variant the browser asks for (en-US, en-AU …) or en-GB.
  • Each catalog is a chunk of its own, loaded only when the language is in use: German users download no catalog. The runtime adds about 1.5 KB gzip to the first download; all English catalogs together are about 24 KB gzip, split by area. A language switch loads every namespace on screen first and then re-renders everything at once.
  • <html lang> follows the language.
  • The server keeps answering in German. Where the app shows a server message (toasts, page errors, the login card), serverText() replaces the common generic ones with the errors catalog.

Labels kept in constants (menu entries in main.tsx, status maps, tab lists) stay German in the code and are translated where they are shown, e.g. t(STATUS_LABEL[s]). Their German text must then be in the catalog – the check below treats a catalog entry as the declaration of such a text.

Translating a page

Section titled “Translating a page”
  1. Add the page’s files to a namespace in web/src/i18n/registry.ts (or create one: an entry in NAMESPACES and a loader in CATALOGS.en). file.tsx#ComponentA,ComponentB covers only those components of a file – useful when a bigger page only shows a button somewhere else.
  2. Wrap every text in t() – JSX text, title, placeholder, aria-label, label/hint props, toast and confirm messages, Error texts users see.
  3. Run npm run i18n:check -- --todo en: it lists the texts still missing in the catalog. Translate them in web/src/i18n/en/<namespace>.ts.
  4. Set complete: true for the namespace and run npm run i18n:check until it is clean. tests/i18n.test.ts runs the same check, so CI keeps it complete.

Keep German texts short and plain; the English ones too. Do not translate brand names, protocol names or merge tags.

What npm run i18n:check reports

Section titled “What npm run i18n:check reports”
Rule Meaning
missing a t('…') text of a namespace declared complete has no translation (in its catalog or in core)
untranslated a German UI text in a file of a complete namespace that is neither wrapped in t() nor in a catalog – JSX text, titles, labels, placeholders, toasts, texts with German words or umlauts
placeholders a translation uses a {placeholder} the German text does not have
unused a catalog entry whose German text appears nowhere in its namespace any more (nor as a text the server sends)
registry a namespace file is missing, or a catalog file is not registered

Brand names, units and examples are allowed in scripts/i18n-check.mjs (ALLOW); a line that is intentionally not translated (an HTTP header, diagnostics for bug reports) carries the comment i18n-ignore.

Adding a language

Section titled “Adding a language”

Community translations are welcome. To add, say, French:

  1. In web/src/i18n/registry.ts add fr: { name: 'Français', intl: 'fr-FR' } to LOCALES and a fr block to CATALOGS with one loader per namespace (core: () => import('./fr/core') …). A namespace without a French catalog simply stays German.
  2. Copy web/src/i18n/en/ to web/src/i18n/fr/ and replace the English values. The keys stay German – the English file next to it shows what each one means.
  3. Add 'fr' to UI_LOCALES in server/modules/language.ts so the language can be saved and is picked from Accept-Language.
  4. Run npm run i18n:check and npm test, take a look at the screens with long words (the sidebar, the settings tabs, the inbox bar on a phone) and open a pull request.

The language appears in every switch by itself (each language is named in its own language).
