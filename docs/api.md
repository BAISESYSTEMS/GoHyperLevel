# API

Basis: `https://<deine-domain>`. Schlüssel unter **Einstellungen → API & Webhooks** anlegen; jeder Schlüssel gehört zu einem Sub-Account.

Maschinenlesbar: **OpenAPI 3.1** unter `GET /api/openapi.json`, als Webseite unter `GET /api/docs.html` (beide ohne Schlüssel). REST-Hooks, Zapier/Make/n8n, „Webhook empfangen“ und der HubSpot-Import: [docs/integrations.md](integrations.md).

```bash
KEY=pghl_…
# Kontakt anlegen oder aktualisieren (Dubletten per E-Mail/Telefon werden zusammengeführt)
curl -X POST https://crm.example.com/api/contacts -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"first_name":"Anna","email":"anna@example.com","tags":["lead"],"custom":{"budget":"5000"}}'

# Kontakte suchen
curl "https://crm.example.com/api/contacts?q=anna&tag=lead&limit=50" -H "Authorization: Bearer $KEY"

# Opportunity anlegen
curl -X POST https://crm.example.com/api/opportunities -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"pipeline_id":"…","contact_id":"…","value":1500}'
```

## Mobile-App

Schnittstelle der nativen [Android-App](app.md#android-app). JSON, Geld in Cent (`*_cents`) plus `currency` (`EUR`), Zeiten ISO-8601 in UTC, Fehler `{error}` auf Deutsch. Jede Listenzeile trägt `location_id` und `location_name`; `?location=all` (Standard) fasst alle sichtbaren Sub-Accounts zusammen, `?location=<id>` nimmt einen (fremd → 403, unbekannt → 404). Bereiche, die ein Kunden-Login oder sein SaaS-Tarif nicht hat, fehlen bei `all` bzw. geben 403 mit dem Grund.

**Anmeldung:** `POST /api/mobile/pair` nur mit Sitzungs-Cookie + `x-pghl: 1` (Login der App-Web-Ansicht), Body `{device_name, platform, app_version}` → `{token: "ghm_…", device_id, user: {id, name, email, role, permissions}}` (Token nur in dieser Antwort). Alle anderen Aufrufe mit `Authorization: Bearer ghm_…` (optional `x-app-version`); unbekannt/abgemeldet → 401, mehr als 300 Anfragen/Minute je Gerät → 429. Der Token gilt nur unter `/api/mobile/*`.

## Undo, history and trash

Journal of every change to the main records, with undo, redo and a 30-day trash – [docs/undo.md](undo.md) for what is covered. Sub-account routes (`x-location-id` or the sub-account key); the person undoes their own changes, admins anyone's; another sub-account always gets 404.

| Route | What |
| --- | --- |
| `GET /api/undo?scope=mine\|all&entity=&actor=&q=&include=undone&before=&limit=` | Changes, newest first, one item per request (a bulk action is one item with `count`). `actor`: `me`, `user`, `agent`, `api_key`, `mcp`, `agency_key`, `app`. Item: `{id, at, label, entity, entity_id, action, actor, actor_kind, count, items?, changes: [{k, l, from, to}], notice, kind: change\|undo, undone_at, can_undo, restorable, reason, removes, expires_at}`; the answer adds `has_more`, `retention_days` |

| `POST /api/undo/:id` `{force?, single?}` | Restore in one transaction → `{ok, label, restored, redo_id, notices}`; 409 with `{conflict, diff}` if the record changed since; 403 not yours / no area; 404; 409 already undone; 410 expired; 422 not restorable |

## Webhooks

Ausgehend: `POST` an deine URL mit `{type, locationId, at, data}` und den Headern `x-pghl-signature-256: sha256=<HMAC-SHA256(secret, body) hex>` (empfohlen) und `x-pghl-signature: sha256(secret + body)` (älteres Verfahren, bleibt für bestehende Empfänger). Neu: `call.missed`, `call.voicemail`, `call.completed` (`{contactId, callId, direction, status, from, to, duration, transcription}`), `voice_ai.completed` – KI-Anruf beendet (`{contactId, callId, sessionId, outcome: booked|transferred|message|opportunity|task|sms_link|answered|hangup|voicemail|limit|error, outcomes, summary, next_step, appointmentId, taskId, opportunityId, message, transferred, turns, duration, from}`) und `google_review.received` (`{contactId?, rating, author, text, link, low}`). Wird ein Termin im verbundenen Google-/Outlook-Kalender gelöscht, kommt `appointment.status_changed` mit `status: "cancelled"` und `source: "google"|"microsoft"`. Ohne eigenen Workflow-Auslöser, aber an Webhooks mit `events: ["*"]` und REST-Hooks „Jedes Ereignis“: `contact.deleted` (`{contactId, erased?}` – auch beim Löschen mehrerer Kontakte, `erased: true` bei der DSGVO-Löschung), `contact.merged` (`{contactId, contact, fromId}`), aus der Projektplanung `task.updated` (`{contactId?, task, projectId, changed}`), `task.deleted` (`{contactId?, taskId, title, projectId, by}`), `task.commented` (`{contactId?, task, comment: {id, body}, mentions}`), `pm.project.deleted` (`{projectId, name}`), `timer.started`, `timer.stopped`, `time.logged` (je `{entry}`), `timesheet.submitted` (`{userId, week}`), `timesheet.decided` (`{userId, week, status}`), dazu `sequence.enrolled` (`{contactId, sequenceId, enrollmentId, userId}`), `billing.cancel_requested` (`{contactId, subscription, productId, immediate}`) und `billing.plan_switched` (`{contactId, subscription, fromProductId, productId, product}`) von der Abo-Seite des Kunden (`/abo/…`, [docs/dunning.md](dunning.md)).

Eingehend (Workflow-Auslöser „Eingehender Webhook“): die im Workflow angezeigte URL mit JSON `{email, phone, first_name, …, tags}` aufrufen (ohne E-Mail, Telefon oder Namen `400`). Auslöser „Webhook empfangen“: `POST /hooks/in/<token>` mit beliebigem JSON (Feldzuordnung im Workflow, optional `X-Signature-256: sha256=<hmac>`, Limit je URL, 429 darüber) – [Details](integrations.md#eingehende-webhooks). Wiederholte Zustellungen werden nur einmal verarbeitet: bei beiden Workflow-Webhooks über die Zustell-ID des Absenders (`webhook-id`, `svix-id`, `Idempotency-Key`, `X-Idempotency-Key`, `X-Webhook-Id`, `X-Delivery-Id`, `X-GitHub-Delivery`, `X-Shopify-Webhook-Id` – Antwort `{ok: true, duplicate: true}`), beim SMS-/E-Mail-Eingang (`/hooks/:locationId/sms|email?key=`) und beim Support-Postfach über die Nachrichten-ID (`MessageSid`, `payload.messageId`, `Message-Id`, auch in `headers`). Stripe, Meta, Twilio-Anrufe, Telegram, Slack und die SMS-/E-Mail-Anbieter erkennen Wiederholungen schon an ihren Ereignis-IDs.

REST-Hooks (Zapier/Make/n8n): Zustellungen als `{id, event, type, location_id, occurred_at, contact_id, contact, data}` mit `x-pghl-signature-256 = sha256=<HMAC-SHA256(secret, body)>`, `x-pghl-signature = sha256(secret + body)`, `x-pghl-event`, `x-pghl-delivery`, `x-pghl-attempt`; Wiederholung nach 1 Min./5 Min./30 Min./2 Std./6 Std., Abo aus nach dreimal 410. Neues Ereignis `task.completed` (`{contactId?, task}`) beim Erledigen einer Aufgabe.

## MCP-Server

`POST /mcp` spricht das Model Context Protocol (Streamable HTTP, JSON-Antworten, zustandslos). Anmeldung mit `Authorization: Bearer <Agentur-Schlüssel>` (alle Projekte) oder einem Sub-Account-Schlüssel (nur dieses Projekt) – oder mit einem OAuth-Token (`pghlo_…`, siehe [OAuth for MCP clients](#oauth-for-mcp-clients)) mit genau derselben Reichweite. Ohne gültige Anmeldung antwortet `/mcp` mit `401` und `WWW-Authenticate: Bearer realm="mcp", resource_metadata="https://<domain>/.well-known/oauth-protected-resource"`. Einrichtung für Codex, Claude Code, Cursor, ChatGPT und Claude.ai: [docs/ai-tools.md](ai-tools.md).

```bash
# Claude Code
claude mcp add --transport http ghl https://crm.example.com/mcp --header "Authorization: Bearer pghla_…"

# Codex (~/.codex/config.toml: [mcp_servers.gohigh] url = "https://crm.example.com/mcp", bearer_token_env_var = "GOHIGH_API_KEY")
```

## Limits

Anfragen ohne gültige Anmeldung werden schon an den Headern abgelehnt. Körper: 1 MB auf öffentlichen Routen (Formular-Uploads, eingehende Mails, Community-Bilder und `/mcp` mit gültigem Schlüssel: 12 MB), 12 MB mit Anmeldung oder Schlüssel. `429` bei mehr als 900 API-Anfragen bzw. 120 öffentlichen Schreibzugriffen je Minute und Adresse. `limit`-Parameter werden auf 1…Maximum begrenzt.

### Provider sign-up links (partner links)

`GET /api/referrals` (any signed-in user) → `{ "<id>": { name, url: "/go/<id>", is_referral, sponsor? } }`. Admins: `GET/PUT /api/agency/referrals` (`{ enabled?, links?: { "<id>": "<https-url>" | "" } }`), `DELETE /api/agency/referrals/clicks`. Public: `GET /go/:provider` → `302` to the resolved address (catalogue ids only, counts clicks per provider). Details: [docs/referrals.md](referrals.md).
